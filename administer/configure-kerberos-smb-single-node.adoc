= Configure o Kerberos para compartilhamentos SMB/CIFS em uma implantação de nó único do AI Data Engine
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Analise compartilhamentos SMB/CIFS de uma implantação de nó único do AI Data Engine (AIDE) usando autenticação Kerberos, para que nenhuma senha fique armazenada na fonte de dados. Após concluir a configuração, o AI Data Engine atualiza o ticket Kerberos automaticamente.

Se você tiver uma implantação com vários nós, consulte link:configure-kerberos-smb-multi-node.html["Configure o Kerberos para compartilhamentos SMB/CIFS em uma implantação do AI Data Engine com vários nós"].



[[before-you-begin]]
== Antes de começar

.Permissões e acesso
* Você tem privilégios de _administrador do AI Data Engine_.
* Você tem acesso à raiz ao host do AI Data Engine.


.Sincronização de rede e horário
* Você revisou o link:../deploy/aide-requirements.html#networking-requirements["requisitos de rede"] e o link:../deploy/aide-requirements.html#kerberos-ad-requirements["Requisitos do Kerberos e do Active Directory"], incluindo a sincronização de tempo e DNS.
* Você verificou que o host do AI Data Engine consegue alcançar o KDC na porta 88, o servidor de arquivos na porta 445 e o seu servidor DNS na porta 53.
* Você verificou se o NTP está ativo no host do AI Data Engine e se o relógio dele está sincronizado com seus controladores de domínio. Para verificar, execute `timedatectl`.


.Active Directory
* Você tem uma conta de serviço de varredura no Active Directory com acesso de leitura aos compartilhamentos SMB/CIFS que deseja verificar. A conta deve oferecer suporte à criptografia AES256.


.Informações a coletar
* Você possui as seguintes informações:
+
[cols="2,4,2"]
|===
| Item | Descrição | Exemplo 


| Endereço IP do KDC | Endereço IP do controlador de domínio que atua como centro de distribuição de chaves Kerberos (KDC) | `10.0.1.50` 


| FQDN do KDC | Nome de domínio totalmente qualificado (FQDN) do mesmo controlador de domínio | `dc.corp.example.com` 


| Domínio | Domínio do Active Directory, em letras minúsculas | `corp.example.com` 


| Realm | Realm do Kerberos, que é o domínio em maiúsculas | `CORP.EXAMPLE.COM` 


| Usuário de varredura | Conta de serviço com acesso de leitura ao compartilhamento | `svc-aide` 


| Senha de varredura | Senha do usuário de varredura. Você a insere somente ao criar o keytab. | Não aplicável 


| FQDN do servidor de arquivos | Nome de domínio totalmente qualificado (FQDN) do servidor de arquivos que hospeda o compartilhamento. Não use um endereço IP. | `filer.corp.example.com` 


| Nome do compartilhamento | Nome do compartilhamento SMB/CIFS | `sharename` 
|===




[[kerberos-files-that-ai-data-engine-uses]]
[[kerberos-file-locations]]
== Arquivos Kerberos que o AI Data Engine utiliza

Você cria os seguintes arquivos no host do AI Data Engine. O instalador cria os `/opt/netapp/aide` diretórios e instala `cifs-utils` automaticamente para oferecer suporte ao acesso SMB autenticado por Kerberos.

[cols="1,2"]
|===
| Arquivo | Localização 


| Configuração do Kerberos | `/etc/krb5.conf` 


| Keytab | `/opt/netapp/aide/kerberos_refresher/datasense.keytab` 


| Arquivo principal | `/opt/netapp/aide/kerberos_refresher/kerberos_creds.env` 


| Cache de tickets, que o AI Data Engine cria ao atualizar o ticket | `/opt/netapp/aide/kerberos_ccache/krb5cc_shared` 
|===


[[create-the-kerberos-files]]
[[create-kerberos-files]]
== Crie os arquivos Kerberos

Forneça ao AI Data Engine a configuração e as credenciais necessárias para obter os tickets Kerberos para a conta de serviço de varredura.

.Passos
. Instale as ferramentas do cliente Kerberos.
+
.. No Ubuntu ou Debian, execute os seguintes comandos.
+
[source, cli]
----
apt-get update -qq
apt-get install -y krb5-user
----
.. No RHEL, CentOS ou Rocky Linux, execute o seguinte comando.
+
[source, cli]
----
dnf -y install krb5-workstation
----


. Defina as variáveis que os comandos a seguir usarão. Substitua cada valor entre colchetes angulares pelo seu valor e não inclua os colchetes angulares. Digite o realm em maiúsculas e o domínio em minúsculas.
+
[source, cli]
----
export KDC_IP="<kdc_ip>"
export KDC_FQDN="<kdc_fqdn>"
export AD_DOMAIN="<domain>"
export REALM="<REALM>"
export SCAN_USER="<scan_user>"
export FILE_SERVER_FQDN="<file_server_fqdn>"
export SHARE_NAME="<share_name>"
----
+
.. Verifique se as variáveis estão definidas.
+
[source, cli]
----
echo "KDC_IP=[${KDC_IP}] REALM=[${REALM}] SCAN_USER=[${SCAN_USER}]"
----
+

NOTE: As variáveis existem apenas na sessão atual do shell. Se você abrir um novo shell, defina-as novamente.



. Crie o arquivo de configuração do Kerberos.
+
[source, cli]
----
tee /etc/krb5.conf >/dev/null <<EOF
[libdefaults]
    default_realm = ${REALM}
    dns_lookup_realm = false
    dns_lookup_kdc = false
    rdns = false
    ticket_lifetime = 24h
    renew_lifetime = 7d
    forwardable = true

[realms]
    ${REALM} = {
        kdc = ${KDC_IP}:88
        admin_server = ${KDC_IP}:749
    }

[domain_realm]
    .${AD_DOMAIN} = ${REALM}
    ${AD_DOMAIN} = ${REALM}
EOF
chmod 644 /etc/krb5.conf
----
+
O arquivo utiliza o endereço IP do KDC para que a autenticação Kerberos não dependa do DNS.

. Crie um keytab para a conta de serviço de varredura.
+
.. Execute `ktutil`.
.. No `ktutil` prompt, digite o seguinte comando. Substitua `<scan_user>` e `<REALM>` pelos seus valores. O `ktutil` prompt não usa as variáveis de shell.
+
[source, cli]
----
addent -password -p <scan_user>@<REALM> -k 1 -e aes256-cts-hmac-sha1-96
----
.. Quando `ktutil` for solicitado a informar uma senha, digite a senha do usuário de varredura.
.. No `ktutil` prompt, digite os seguintes comandos.
+
[source, cli]
----
wkt /tmp/krb5.keytab
quit
----


. Teste o keytab.
+
[source, cli]
----
klist -kt /tmp/krb5.keytab
kinit -kt /tmp/krb5.keytab "${SCAN_USER}@${REALM}"
klist
kdestroy
----
+
O segundo `klist` comando deve exibir um ticket válido para o usuário de varredura. Um ticket confirma que o keytab e a conexão com o KDC estão funcionando. Se `kinit` falhar, consulte <<troubleshoot-kerberos,Solução de problemas de autenticação Kerberos>>.

. Instale o keytab e depois exclua a cópia temporária.
+
[source, cli]
----
install -o root -g 4321 -m 640 /tmp/krb5.keytab /opt/netapp/aide/kerberos_refresher/datasense.keytab
rm -f /tmp/krb5.keytab
----
+
O atualizador de tickets é executado como usuário raiz com ID de grupo 4321. O keytab e o arquivo do principal devem ser legíveis por esse grupo e por nenhum outro usuário.

. Crie o arquivo principal. O `KRB5_RENEW_INTERVAL_H` valor é o intervalo de renovação do ticket em horas.
+
[source, cli]
----
tee /opt/netapp/aide/kerberos_refresher/kerberos_creds.env >/dev/null <<EOF
KRB5_USER=${SCAN_USER}
KRB5_REALM=${REALM}
KRB5_RENEW_INTERVAL_H=3
EOF
chgrp 4321 /opt/netapp/aide/kerberos_refresher/kerberos_creds.env
chmod 640 /opt/netapp/aide/kerberos_refresher/kerberos_creds.env
----




[[verify-name-resolution]]
== Verifique a resolução de nomes

O AI Data Engine resolve o servidor de arquivos e o KDC usando as configurações de DNS do host. Verifique primeiro a resolução de nomes e altere as configurações de DNS somente se um nome não for resolvido.

.Passos
. Verifique se o servidor de arquivos e o KDC são resolvidos por FQDN.
+
[source, cli]
----
nslookup "${FILE_SERVER_FQDN}"
nslookup "${KDC_FQDN}"
----
. Confira o resultado.
+
.. Se ambos os nomes forem resolvidos para os endereços IP corretos, continue em <<start-first-ticket-refresh,Inicie a primeira atualização do ticket>>.
.. Se qualquer um dos nomes não for resolvido, conclua <<fix-name-resolution,Corrigir resolução de nomes>> e depois retorne a este procedimento.






[[start-the-first-ticket-refresh]]
[[start-first-ticket-refresh]]
== Inicie a primeira atualização do ticket

O AI Data Engine atualiza o ticket Kerberos da conta de serviço de varredura a cada três horas. Inicie a primeira atualização para que você possa varrer compartilhamentos imediatamente.


NOTE: Não adicione uma `kinit` entrada ao crontab do host. O AI Data Engine atualiza os tickets automaticamente.

.Passos
. Inicie uma tarefa de atualização, aguarde sua conclusão e exiba seu log.
+
[source, cli]
----
export KUBECONFIG=/etc/rancher/k3s/k3s.yaml
JOB="ds-krb5-manual-$(date +%s)"
kubectl -n aide create job "${JOB}" --from=cronjob/ds-krb5-ticket-refresher
kubectl -n aide wait --for=condition=complete "job/${JOB}" --timeout=120s
kubectl -n aide logs "job/${JOB}"
----
. Verifique se o cache de tickets compartilhado existe e tem um carimbo de data/hora recente.
+
[source, cli]
----
ls -l /opt/netapp/aide/kerberos_ccache/krb5cc_shared
----


.Resultado
O log do trabalho mostra que um ticket foi obtido para o usuário de varredura.



[[verify-the-kerberos-configuration]]
[[verify-kerberos-configuration]]
== Verifique a configuração do Kerberos

Antes de adicionar o compartilhamento, verifique se o AI Data Engine consegue usar os arquivos Kerberos e resolver nomes. Se você abriu um novo shell, defina a `FILE_SERVER_FQDN` variável novamente e defina `KUBECONFIG` como mostrado em <<start-first-ticket-refresh,Inicie a primeira atualização do ticket>>.

.Passos
. Localize o pod do serviço de montagem.
+
[source, cli]
----
POD=$(kubectl -n aide get pod -l app.kubernetes.io/name=ds-mount-server -o jsonpath='{.items[0].metadata.name}')
----
. Verifique se o AI Data Engine consegue resolver o servidor de arquivos.
+
[source, cli]
----
kubectl -n aide exec "${POD}" -- nslookup "${FILE_SERVER_FQDN}"
----
. Verifique se o AI Data Engine tem um ticket para o usuário de varredura.
+
[source, cli]
----
kubectl -n aide exec "${POD}" -- klist
----


.Resultado
O servidor de arquivos resolve para o endereço IP correto, e `klist` mostra um tíquete para o usuário de varredura.



[[add-an-smbcifs-data-source-that-uses-kerberos]]
== Adicione uma fonte de dados SMB/CIFS que use Kerberos

Adicione o compartilhamento como uma fonte de dados e inicie as varreduras para que o AI Data Engine possa começar a analisar seus dados.

.Passos
. Na interface do usuário do AI Data Engine, selecione *Configuração*.
. Na guia *Sistemas verificados*, selecione *Adicionar sistema*.
. Selecione *Grupo de compartilhamentos de arquivos*.
. Digite um nome para o grupo.
. Insira o caminho de compartilhamento no formato `<file_server_fqdn>/<share_name>`. Substitua os espaços reservados pelos seus valores. Não use endereço IP.
. Para o método de autenticação, selecione *Kerberos*. Deixe os campos de nome de usuário e senha em branco.
. Revise suas seleções e selecione *Confirm*.
. Selecione *Ativar verificações* para o novo sistema.


Para obter mais informações sobre como conectar fontes de dados, consulte link:../data-sources/connect-data-source.html["Conecte uma fonte de dados ao AI Data Engine"].



[[fix-name-resolution]]
== Corrigir resolução de nomes

Execute este procedimento somente se o servidor de arquivos ou o KDC não forem resolvidos por FQDN. Ele define o seu servidor DNS do Active Directory como o servidor de nomes do host. Se você abriu um novo shell, defina as `KDC_IP` e `AD_DOMAIN` variáveis novamente.

.Passos
. Verifique se o servidor DNS do seu Active Directory também resolve nomes externos.
+
.. Execute o seguinte comando. Substitua `<external_fqdn>` por um nome fora do seu domínio que o AI Data Engine precisa acessar. Por exemplo, use um endpoint listado em link:../deploy/aide-requirements.html#outbound-internet-access["Acesso à internet de saída"].
+
[source, cli]
----
nslookup <external_fqdn> "${KDC_IP}"
----
.. Se o comando falhar, peça ao administrador do Active Directory para habilitar o encaminhamento de DNS e, em seguida, repita esta etapa.


. Faça um backup `/etc/resolv.conf`, e configure seu servidor DNS do Active Directory como servidor de nomes.
+
[source, cli]
----
cp /etc/resolv.conf /etc/resolv.conf.bak
ORIG_SEARCH=$(grep '^search' /etc/resolv.conf.bak | head -1 | cut -d' ' -f2-)
printf 'search %s\nnameserver %s\n' "${ORIG_SEARCH}" "${KDC_IP}" > /etc/resolv.conf
----
. Impeça que o gerenciador de rede substitua as configurações de DNS após reiniciar.
+
.. No RHEL com NetworkManager, execute os seguintes comandos.
+
[source, cli]
----
mkdir -p /etc/NetworkManager/conf.d
printf '[main]\ndns=none\n' > /etc/NetworkManager/conf.d/90-dns-none.conf
systemctl reload NetworkManager
----
.. No Ubuntu com systemd-resolved, execute os seguintes comandos.
+
[source, cli]
----
mkdir -p /etc/systemd/resolved.conf.d
printf '[Resolve]\nDNS=%s\nDomains=%s\n' "${KDC_IP}" "${AD_DOMAIN}" > /etc/systemd/resolved.conf.d/ad-dns.conf
systemctl restart systemd-resolved
----


. Reinicie o CoreDNS para que o AI Data Engine use as novas configurações de DNS. O CoreDNS encaminha consultas de nomes fora do cluster para os servidores de nomes em `/etc/resolv.conf`, portanto precisa reiniciar para que a alteração seja aplicada.
+
[source, cli]
----
export KUBECONFIG=/etc/rancher/k3s/k3s.yaml
kubectl -n kube-system rollout restart deployment coredns
kubectl -n kube-system rollout status deployment coredns --timeout=120s
----
. Verifique novamente a resolução de nomes. Consulte <<verify-name-resolution,Verifique a resolução de nomes>>.




[[update-the-kerberos-configuration-file]]
[[update-kerberos-configuration]]
== Atualize o arquivo de configuração do Kerberos

Se você substituir `/etc/krb5.conf` após a instalação, por exemplo, copiando um novo arquivo sobre ele, o AI Data Engine continuará a usar o arquivo anterior até você reiniciar os serviços afetados.

.Passos
. Reinicie o serviço de montagem e exclua as tarefas de atualização de tickets anteriores.
+
[source, cli]
----
export KUBECONFIG=/etc/rancher/k3s/k3s.yaml
kubectl -n aide rollout restart daemonset ds-mount-server
kubectl -n aide delete job -l app.kubernetes.io/name=ds-krb5-ticket-refresher --ignore-not-found
----
. Inicie uma nova atualização de ticket. Consulte <<start-first-ticket-refresh,Inicie a primeira atualização do ticket>>.




[[troubleshoot-kerberos-authentication]]
[[troubleshoot-kerberos]]
== Solução de problemas de autenticação Kerberos

Identifique a causa de uma falha do Kerberos e restaure a verificação dos seus compartilhamentos SMB/CIFS.

[cols="2,3,3"]
|===
| Sintoma | Possível causa | Resolução 


| O erro *IP não permitido com Kerberos* aparece quando você adiciona um compartilhamento. | O caminho de compartilhamento utiliza um endereço IP. | Insira o caminho do compartilhamento como um FQDN. 


| `kinit` falha ao testar o keytab, ou nenhum ticket é emitido. | A senha ou o realm está incorreto, o realm não está em maiúsculas, a conta de varredura não oferece suporte à criptografia AES256, o host não consegue alcançar o KDC na porta 88 ou o relógio do host difere do KDC em mais do que a defasagem permitida. | Verifique a senha e o realm e confirme se a conta suporta criptografia AES256. Abra a porta 88 para o KDC e confirme se o NTP está ativo no host. Em seguida, crie o keytab novamente. 


| A tarefa de atualização do ticket falha, ou nenhum cache de tickets é criado. | O keytab, o arquivo principal ou `/etc/krb5.conf` está ausente ou vazio, ou a propriedade e as permissões do grupo estão incorretas. | Verifique se os arquivos existem nos locais listados em <<kerberos-file-locations,Arquivos Kerberos que o AI Data Engine utiliza>>. Verifique se o keytab e o arquivo do principal têm grupo 4321 e modo 640. Verifique se o diretório de cache de tickets pertence a `root:4321` com modo 770. Se não pertencer, execute  `chown root:4321 /opt/netapp/aide/kerberos_ccache && chmod 770 /opt/netapp/aide/kerberos_ccache`. 


| O nome do servidor de arquivos ou do KDC não é resolvido no host. | O host não utiliza um servidor DNS capaz de resolver os nomes do seu Active Directory. | Conclua <<fix-name-resolution,Corrigir resolução de nomes>>. 


| Os nomes são resolvidos no host, mas não dentro do AI Data Engine. | Você não reiniciou o CoreDNS após alterar `/etc/resolv.conf`. | Reinicie o CoreDNS. Consulte <<fix-name-resolution,Corrigir resolução de nomes>>. 


| Os nomes externos não são resolvidos no AI Data Engine depois que você configura o servidor DNS do Active Directory. | O servidor DNS do Active Directory não encaminha consultas externas. | Verifique se  `nslookup <external_fqdn> "${KDC_IP}"` retorna um resultado. Caso contrário, peça ao administrador do Active Directory para habilitar o encaminhamento de DNS ou adicione seu servidor DNS original como um segundo servidor de nomes em  `/etc/resolv.conf`. 


| O erro *mount error(126)* aparece. | O AI Data Engine não consegue ler `/etc/krb5.conf`. | Verifique se `/etc/krb5.conf` existe no host e se `+kubectl -n aide exec "${POD}" -- cat /etc/krb5.conf+` exibe seu conteúdo. 


| As alterações em `/etc/krb5.conf` não entram em vigor. | O arquivo foi substituído após a instalação, e o AI Data Engine ainda utiliza o arquivo anterior. | Consulte <<update-kerberos-configuration,Atualize o arquivo de configuração do Kerberos>>. 


| O comando  `ktutil`,  `kinit` ou  `klist` não foi encontrado. | As ferramentas de cliente Kerberos não estão instaladas no host. | Instale as ferramentas do cliente Kerberos. Consulte <<create-kerberos-files,Crie os arquivos Kerberos>>. 


| O `/etc/resolv.conf` arquivo retorna às suas configurações anteriores após uma reinicialização. | O gerenciador de rede sobrescreve o arquivo. | Impeça o gerenciador de rede de sobrescrever as configurações de DNS. Consulte <<fix-name-resolution,Corrigir resolução de nomes>>. 
|===


[[remove-the-kerberos-configuration]]
[[remove-kerberos-configuration]]
== Remova a configuração do Kerberos

Se você não fizer mais varreduras em compartilhamentos SMB/CIFS com Kerberos, remova a fonte de dados e os arquivos do Kerberos.

.Passos
. Na interface do usuário do AI Data Engine, exclua a fonte de dados SMB/CIFS que usa Kerberos.
. Exclua os arquivos do Kerberos.
+
[source, cli]
----
rm -f /opt/netapp/aide/kerberos_refresher/datasense.keytab
rm -f /opt/netapp/aide/kerberos_refresher/kerberos_creds.env
rm -f /opt/netapp/aide/kerberos_ccache/krb5cc_shared
----
. Se nenhum outro aplicativo no host o estiver usando, exclua-o `/etc/krb5.conf`.
. Se você alterou as configurações de DNS, restaure as configurações originais.
+
.. Restaure o backup de `/etc/resolv.conf`.
+
[source, cli]
----
cp /etc/resolv.conf.bak /etc/resolv.conf
----
.. No RHEL em que você adicionou uma configuração do NetworkManager, remova-a.
+
[source, cli]
----
rm -f /etc/NetworkManager/conf.d/90-dns-none.conf
systemctl reload NetworkManager
----
.. No Ubuntu, onde você adicionou uma configuração do systemd-resolved, remova-a.
+
[source, cli]
----
rm -f /etc/systemd/resolved.conf.d/ad-dns.conf
systemctl restart systemd-resolved
----
.. Reinicie o CoreDNS.
+
[source, cli]
----
export KUBECONFIG=/etc/rancher/k3s/k3s.yaml
kubectl -n kube-system rollout restart deployment coredns
----
