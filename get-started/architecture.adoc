= Arquitetura do AI Data Engine
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
O AI Data Engine (AIDE) é executado na infraestrutura que você fornece. O Metadata Engine examina seu storage e cria um catálogo pesquisável. O NetApp Console gerencia sua implantação por meio de um agente do Console. Uma opção de servidor Model Context Protocol (MCP) permite que os clientes de AI pesquisem o catálogo dentro dos limites que você define.



[[components]]
== Componentes

O painel, a investigação e as políticas do AI Data Engine no NetApp Console funcionam com base no catálogo de metadados. Os seguintes componentes constroem o catálogo, conectam-no ao NetApp Console e fornecem acesso governado para clientes de IA.



[[metadata-engine]]
=== Metadata Engine

O Metadata Engine é a principal funcionalidade do AI Data Engine. Ele examina as fontes de dados que você conecta, extrai metadados e os armazena em um catálogo pesquisável. Ele não lê nem classifica o conteúdo dos arquivos. O Metadata Engine atualiza o catálogo a cada ciclo de varredura, detectando adições, alterações e exclusões em seus sistemas de storage.



[[netapp-console-agent]]
=== Agente do NetApp Console

O AI Data Engine requer um agente do NetApp Console implantado no seu ambiente. O agente do Console é um componente de plataforma de uso geral da NetApp que mantém a conectividade entre o seu ambiente e o NetApp Console. Ele gerencia a autenticação e a comunicação entre o NetApp Console e a sua implantação do AI Data Engine. Os serviços de varredura e catalogação são executados na sua implantação do AI Data Engine, não no agente do Console.


NOTE: O agente do Console não é específico do AI Data Engine. Se você já tiver um agente do Console implantado para outros NetApp serviços, poderá usar o mesmo agente. Para obter instruções de implantação do agente do Console, consulte a link:https://docs.netapp.com/us-en/console-setup-admin/concept-agents.html["Documentação do agente do NetApp Console"].



[[governed-access-gateway]]
=== Gateway de Acesso Governado

O Governed Access Gateway é o servidor MCP para o AI Data Engine. Ele permite que os clientes de IA pesquisem o catálogo de metadados. O gateway é executado na sua implantação do AI Data Engine, e os clientes de IA se conectam a ele por HTTPS pela sua rede corporativa ou por VPN. O agente do Console não retransmite o tráfego MCP.

O Microsoft Entra ID autentica os usuários, e o gateway limita cada cliente de AI às coleções que o usuário está autorizado a pesquisar. O gateway oferece suporte apenas à pesquisa e à marcação de metadados, e somente usuários avançados podem marcar arquivos. Ele não recupera o conteúdo dos arquivos.

link:../mcp/learn-about-mcp.html["Saiba mais sobre o acesso governado à IA"].



[[deployment-types]]
== Tipos de implantação

O AI Data Engine suporta dois tipos de implantação. Ambos executam os serviços do AI Data Engine no Kubernetes.

Implantação de nó único do AIDE:: Executa em uma única máquina virtual Linux fornecida por você. O instalador provisiona o k3s e os componentes de suporte automaticamente. Uma implantação em um único nó não oferece alta disponibilidade nem escalabilidade horizontal.
Implantação multinó do AIDE:: Funciona em um cluster Kubernetes que você fornece e se destina a ambientes maiores que exigem alta disponibilidade.


Para obter informações sobre plataformas compatíveis, dimensionamento e requisitos de infraestrutura, consulte link:../deploy/aide-requirements.html["Requisitos do AIDE"].

Cada tipo de implantação também possui um procedimento separado para ambientes que acessam a internet somente por meio de um proxy de saída. Consulte link:../deploy/configure-proxy.html["Saiba mais sobre proxies para o AI Data Engine"].

link:../deploy/deployment-overview.html["Saiba mais sobre as opções de implantação"].



[[data-flow]]
== Fluxo de dados

O AI Data Engine usa dois caminhos separados: um que cria o catálogo e o disponibiliza para a NetApp Console, e outro que atende os clientes de IA.



[[metadata-scanning-and-netapp-console-access]]
=== Varredura de metadados e acesso ao NetApp Console

. Você implanta o AI Data Engine em uma infraestrutura que você gerencia e o conecta a um agente do NetApp Console.
. Você conecta as fontes de dados que deseja que o AI Data Engine catalogue em *Fontes de dados*. Para obter mais informações, consulte link:../data-sources/connect-data-source.html["Conecte uma fonte de dados"].
. O Metadata Engine analisa as fontes de dados para extrair metadados e os indexa no catálogo.
. No NetApp Console, o painel exibe insights de storage do catálogo, e a Investigação permite consultar o catálogo diretamente com filtros de metadados.
. Você pode salvar critérios de pesquisa como políticas e executá-las novamente para identificar arquivos correspondentes, além de poder agir sobre arquivos da Investigation.



NOTE: O catálogo reflete metadados coletados durante a varredura. As alterações nos arquivos de origem aparecem no catálogo depois que os arquivos e diretórios afetados são verificados novamente e os resultados são indexados.



[[governed-ai-access]]
=== Acesso controlado à IA

. Você configura o Microsoft Entra ID, habilita coleções para acesso de IA e escolhe quais usuários podem pesquisar em cada coleção.
. Um usuário conecta um cliente de IA ao endpoint HTTPS do Governed Access Gateway e faz login com o Microsoft Entra ID.
. O gateway verifica o acesso do usuário e encaminha as solicitações autorizadas para o Metadata Engine.
. O cliente de AI pesquisa os metadados nas coleções que o usuário pode acessar e nas quais pode realizar ações.
